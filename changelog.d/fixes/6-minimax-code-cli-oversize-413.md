- **fix(sse):** a request that does not fit the SSE hub of the local MiniMax Code CLI is refused with a request-scoped 413 instead of a 500 — the overflow of the hub (`SSE subscriber overflow: <n> items / <n> bytes`) and the run status `limit_exceeded` are a property of the request, but the 500 was renamed to a 502 inside the 200 SSE stream, and a 502 is in the model-lockout list, so one oversized request took the MiniMax leg out of every combo for minutes and the next request answered 503. The failure is now marked as `invalid_request_error`, which the fallback layer keeps out of the model lockout, and the local transport has a second ceiling of 500000 bytes of prompt (the hub of the CLI holds at most `512 * 1024 = 524288` bytes and counts the request in UTF-8 bytes), so a request that fits the token estimate but not the hub is refused before the CLI is spawned ([#6](https://github.com/megamen32/OmniRoute/pull/6))
